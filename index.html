1Install Docker Package

Update your system first, then install Docker.

$ sudo apt update
$ sudo apt install docker.io

What's happening: apt update refreshes the package list, and docker.io installs the Docker engine.

2Install Docker Compose

One command to run several containers together.

$ sudo apt install docker-compose

What's happening: Frappe needs several containers running together — Frappe, MariaDB, and Redis. Docker Compose manages all of them with a single command.

3Give Your User Docker Permission

Add your user to the docker group so you don't need sudo every time.

$ sudo usermod -aG docker $USER

Apply the new group without logging out:

$ newgrp docker

Check that it works:

$ docker ps

What's happening: By default only root can talk to the Docker daemon. Adding yourself to the docker group lets you run Docker commands as your normal user.

Don't skip this step. Without it you will hit "permission denied while trying to connect to the Docker daemon" errors later.

If newgrp docker does not work, log out and log back in, or restart your laptop.

4Clone the Frappe Docker Repo

Download the official project and prepare the dev config.

$ git clone https://github.com/frappe/frappe_docker.git

Go inside the folder:

$ cd frappe_docker

Copy the example devcontainer config into .devcontainer:

$ cp -R devcontainer-example .devcontainer

What's happening: The .devcontainer folder tells Docker which containers to build for development. It is a hidden folder — use ls -a to see it.

5Setup Bench

Initialize bench, then move into the bench folder.

$ bench init --skip-redis-config-generation frappe-bench
$ cd frappe-bench

Want a specific version instead?

Use the same command with a branch name:

$ bench init --skip-redis-config-generation --frappe-branch version-14 frappe-bench

What's happening: --skip-redis-config-generation is used because Redis runs in its own separate container, so bench does not need to generate its own Redis config.

Run only one of the two bench init commands. Use the branch version if you need a specific release, otherwise use the first one.

6Point Bench to the Right Containers

By default bench looks for the database and Redis on localhost. Here they run in separate containers, so we give bench their real addresses. Run these inside the container.

$ bench set-config -g db_host mariadb
$ bench set-config -g redis_cache redis://redis-cache:6379
$ bench set-config -g redis_queue redis://redis-queue:6379
$ bench set-config -g redis_socketio redis://redis-queue:6379
SettingPoints to
db_hostMariaDB container
redis_cacheCache container
redis_queueBackground jobs container
redis_socketioReal-time updates container

What's happening: The -g flag means global, so this setting applies to all sites.

Do not skip this step, otherwise you will get a database connection error while creating the site.

7Install Bench Requirements

Pull in the Python and Node dependencies that your apps need.

$ bench setup requirements

What's happening: This reads every app's requirement files and installs the missing Python packages and Node modules into the bench.

Run this again any time you add a new app or pull new code, so the dependencies stay in sync.

8Create a New Site

Replace site_name with your own name, for example mysite.localhost.

$ bench new-site site_name.localhost

Always end the site name with .localhost.

This command asks for the MySQL root password and an Administrator password. Remember the Administrator password — you will use it to log in.

9Create a New App

Replace ap_name with your own app name.

$ bench new-app ap_name

Use lowercase letters and underscores. my_app is correct; My App and my-app will fail.

It will ask for App Title, Description, Publisher and so on. Press Enter to skip any of these.

10Install the App on Your Site

Connect the app you just made to the site you just made.

$ bench --site site_name install-app appname

What's happening: site_name is the site from Step 8, and appname is the app from Step 9.

Done — your Frappe site and custom app are ready.
